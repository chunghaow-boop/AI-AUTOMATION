## THE DOWNLOADS BUG, DIAGNOSED

`mv` across mounts fails at the unlink step — but **the copy half succeeds first**. So
the file DID arrive and the command reported failure. That is why files looked "stuck"
in Downloads: they were in both places.

| operation | result |
|---|---|
| `cp` Downloads → AI | WORKS, md5 verified |
| `rm` anywhere on a mount | BLOCKED, always |
| `mv` across mounts | copy succeeds, delete fails |
| `mv` within one mount | WORKS |

**Rule: Downloads → AI is always `cp`, never `mv`.** Then delete the original yourself.
Also: `device_commit_files` caps at 20MB/file — several refs exceed it; `cp` has no cap.
